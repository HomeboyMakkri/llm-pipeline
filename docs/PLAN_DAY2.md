# План Day 2 — архитектура промптов и качество ответа

Источник: [`tasks/day02.md`](../tasks/day02.md). Исходное состояние: [`docs/PLAN_DAY1.md`](PLAN_DAY1.md), [`SPEC.md`](../SPEC.md).

**Один запрос пользователя — один пункт плана.** Например: «Выполни пункт 1 из `docs/PLAN_DAY2.md`». Работаем по порядку: перед выбранным пунктом кратко объясняем цель и новые понятия, после — сообщаем результат проверки и останавливаемся. Пункт отмечаем только после его проверки. Запросы к DeepSeek — отдельное понятие: пункты 3 и 5 предусматривают платные прогоны, остальные выполняются локально.

## Цель и поток данных

Сейчас `main.py` читает `stdin`, `prompts.py` собирает одну строку, а `llm_client.py` отправляет её как сообщение `user`. После изменений поток будет таким: `stdin` → `prompts.py` формирует `system` и `user` → `llm_client.py` передаёт сообщения в DeepSeek → `main.py` печатает текст ответа. `system` задаёт общие правила поведения модели, `user` — конкретную задачу и исходный текст. Формат запрашиваем в промпте, но не считаем гарантированным. JSON, схема, автоматическая валидация, повторы и новые зависимости не входят в этот день.

**Day 1 — контроль**
