# Спецификация

## Назначение

Учебный Python-проект для изучения LLM API и построения пайплайна обработки текста. Общее задание и критерии по этапам находятся в `tasks/overall.md` и `tasks/day01.md`–`tasks/day07.md`.

## Текущие решения

- Первый провайдер — DeepSeek через совместимый API; клиент использует библиотеку `openai` и загружает `.env` через `python-dotenv`. Настройки: `DEEPSEEK_API_KEY`, `LLM_BASE_URL` и `LLM_MODEL`. Формирование запроса и извлечение ответа проверены локально; клиент также использован для реальных запросов в эксперименте Day 2.
- Виртуальное окружение находится в `.venv` в корне проекта; README описывает установку в него и текущее состояние проекта.
- Проект развивается по дням; функциональность следующих дней не считается реализованной заранее.

## День 1

Программа принимает произвольный текст без изменения исходного кода и обращается к модели. Ожидаемый результат содержит краткое содержание, три ключевые мысли и короткий полезный ответ; его можно просмотреть в читаемом структурированном виде.

Запуск: `python -m llm_pipeline.main`. Программа читает текст из стандартного ввода до конца потока и выводит ответ модели. Поток локально проверен с подставным HTTP-ответом без обращения к API.

Вызов API, шаблон промпта и сборка программы разделены. Подготовлены минимум три примера; критерий дня включает их реальный прогон через API и проверку результатов. Локальные проверки могут дополнять этот прогон, но не заменяют его.

Строгая схема, формальная валидация и расширенная обработка сбоев относятся к следующим этапам по ТЗ. Формат первого ответа не следует считать гарантированным только потому, что он запрошен в промпте.

## День 2 — пункт 1

`prompts.py` формирует список сообщений: `system` с общими правилами опираться на исходный текст и не выдумывать факты, затем `user` с исходной инструкцией о трёх частях и текстом пользователя. `get_response(messages)` передаёт готовый список клиенту API; инструкции не находятся в клиенте. CLI по-прежнему читает `stdin` и выводит ответ в `stdout`.

Локальная проверка CLI с `httpx.MockTransport` подтвердила порядок сообщений, передачу инструкций и полного ввода, а также вывод подставного ответа. Реальные вызовы DeepSeek для этого пункта не выполнялись; качество ответа модели не проверено.

## День 2 — пункт 2

`USER_PROMPT_TEMPLATE` отделяет инструкцию от исходного текста и запрашивает разделы «Краткое содержание», «Ключевые мысли» и «Итоговый ответ» в этом порядке. `build_prompt` подставляет текст целиком; числовых ограничений длины пока нет. Запрошенный формат не гарантирует формат ответа модели.

Локальная проверка CLI с `httpx.MockTransport` подтвердила порядок разделов в инструкции и неизменённую передачу многострочного текста с кириллицей и фигурными скобками. Вызовов API не было.

## День 2 — пункт 3

На трёх текстах выполнено 12 реальных запросов DeepSeek: варианты A/B/C с общим `system` и контроль Day 1 без `system`. По ручной оценке предварительно выбран C; точные шаблоны, матрица, ошибки ответов и ограничения сравнения записаны в `docs/PLAN_DAY2.md`. Основной шаблон и CLI пока не изменены; реальный прогон штатного CLI в этом пункте не выполнялся.
