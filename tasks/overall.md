🧠 🧠 LLM
📋 llm_overall

Комплексное задание: LLM пайплайн для интеллектуальной обработки текста

🎯 Цель проекта — разработать прикладной LLM-сервис на Python, который принимает текст, извлекает из него структуру, классифицирует тип запроса, генерирует полезный ответ и устойчиво работает при типичных ошибках модели. Все этапы проекта должны быть реализованы как единый пайплайн, а не как набор разрозненных вызовов LLM.

Проект состоит из 7 этапов, соответствующих 7 дням разработки, и финальной интеграции.

📋 Общая концепция проекта

Вы разрабатываете модульный LLM pipeline, который умеет:
- 🧠 принимать сырой текст пользователя
- ✂️ делать summary и выделять ключевые мысли
- 🏷️ классифицировать тип запроса
- 📦 возвращать структурированный JSON
- 💬 генерировать итоговый полезный ответ
- 🛡️ обрабатывать невалидные ответы модели и сбои
- 🔧 расширяться под будущие блоки RAG и Agents

Важно по scope:
Это учебный single-pipeline mini-product, а не полноценная production-платформа. Задача — собрать один надёжный LLM workflow с понятной структурой, а не пытаться покрыть все сценарии работы с моделями сразу.

🏗️ Ключевые концепции
В проекте должны учитываться:
- 🤖 работа с LLM API
- 📝 prompt engineering
- 📐 structured output и валидация схемы
- 🔀 routing по типу запроса
- ⛓️ multi-step обработка
- ⚠️ guardrails, retries, fallback
- 🧪 проверяемость и воспроизводимость результатов

## 🛠️ Технологический стек

- Python — основной язык
- OpenAI API или совместимый LLM API
- pydantic — для валидации структурированного ответа
- json — для работы с ответами модели
- logging — для логирования пайплайна
- python-dotenv — для ключей и конфигурации

## 📋 Общие требования

1. 🤖 Все обращения к модели должны быть вынесены в отдельный клиент или модуль
2. 🧱 Промпты должны быть отделены от основной логики пайплайна
3. 📦 Структурированный ответ должен валидироваться схемой
4. 🔀 Классификация запроса должна влиять на итоговый ответ
5. ⚠️ Нужно обрабатывать пустые ответы, плохой JSON и ошибки API
6. 📝 Все ключевые этапы должны логироваться
7. 🧪 Проект должен содержать набор тестовых текстов или demo-примеров

## 🎉 Критерии успешного завершения

К концу 7 дней система должна уметь:
- 📥 принимать произвольный текст
- 🧠 строить summary и key points
- 🏷️ определять категорию запроса и intent
- 📦 возвращать валидный structured JSON
- 💬 строить финальный ответ на основе routing logic
- 🔄 выполнять несколько шагов подряд как единый pipeline
- 🛡️ не падать от типичных ошибок LLM и корректно обрабатывать сбои

## 📁 Рекомендуемая структура проекта

- main.py или app.py
- llm_client.py
- prompts.py
- schemas.py
- pipeline.py
- utils.py
- .env.example
- README.md
- examples/ или sample_inputs/

Каждый следующий этап усложняет предыдущий функционал и расширяет архитектуру.
